# Architecture

A modular monolith: one Next.js application with Payload CMS 3 embedded, one PostgreSQL
database, and (later) a background worker built from the same code for media processing,
ZIP downloads and notifications.

```
Browser ──> Cloudflare (DNS, CDN, WAF) ──> Coolify proxy ──> app container (Next.js + Payload)
                                                              │
                                                              ├── PostgreSQL (internal network only)
                                                              ├── worker container (planned)
                                                              └── Private object storage (R2/S3, planned)
```

## Current state (foundation)

- Payload admin at `/admin`, REST API at `/api/*` (GraphQL disabled).
- Collections: `users` (roles, account lockout), `media` (public website images),
  `services`. Global: `site-settings` (company details, contact, social links).
- Roles: Super Administrator, Administrator, Production Manager, Photographer, Videographer,
  Editor, Finance Manager, Event Organizer, Client. Only staff can open the admin panel.
- Public homepage reads site settings and published services with public access rules.

## Planned

See `docs/planning/platform-analysis.md` section 6 for the order of the next phases.
Private client media will use presigned multipart uploads straight to object storage,
derivatives generated by a worker, and short-lived signed URLs issued after an authorization check.
